# 프로젝트 세카이 랜덤 디펜스 — 플레이 경험 개편 작업 기준

> 기준일: 2026-11-15. 이 문서는 '완료'를 선언하는 보고서가 아니라 변경 사항을 검증하기 위한 체크리스트다.
> 사용자 피드백 8가지: 재미 부족 / 상호작용 대사 부족 / 이펙트 부족 / UI 엉성함 / 맵 디자인 부족 / 적 디자인 부족 / 위험 요소 없음 / UI 불친절함.

## 유지할 것

- 비영리 HTML5 팬게임, 원본 캐릭터 26명, 기존 캐릭터 스프라이트, 1~4성 합성 및 1x/2x 속도 조작
- 11×12 정사각 타일·한 개의 폐회로 이동 경로·모바일 세로/가로·PC 지원
- 캐릭터 디자인과 의상 임의 변경 금지. 새로운 아트가 필요하면 기존 그림체 기준으로 검토
- 과한 네온/광택/효과음 도배 금지. 이펙트는 명확한 정보와 타격감을 위한 것
- 빠른 임시 CSS 덮어쓰기보다 일관된 UI 디자인과 기기별 실제 화면 검수
- 사용자가 확인하지 않은 미술 방향을 '최종 확정'으로 간주하지 않기

- [x] 최종 정리 시간 표시와 완료/시간 초과/무한 모드 분기 회귀 테스트 작성

### 1. 재미·위험 요소 (문제 1, 7, 8)
- [ ] 방해형 적 1종, 보스의 예고형 위험 행동 1종을 최소 구현으로 검증
- [ ] 경고 → 대응 방법 → 성공/실패 피드백이 한눈에 이해되는지 확인
- [ ] 유닛 배치/이동/합성이 적 대응에 의미 있는 선택인지 테스트
- [ ] 위험을 강제하는 무작위 처벌·사전 예고 없는 공격 금지

### 2. 맵·적 디자인 (문제 5, 6)
- [ ] 7개 맵별 고유한 지형·위험·전략적 차이 정의
- [ ] 적 7종을 작은 해상도에서도 실루엣과 움직임으로 구별
- [ ] 전투판, 캐릭터, 적의 선 굵기·채도·그림자·화풍 통일
- [ ] 맵마다 실제 플레이 차이를 확인하기 전 신규 맵 수 늘리지 않기

### 3. UI/UX 전체 설계 (문제 4, 8)
- [ ] 전투 화면의 정보 우선순위(위험/웨이브/소환/합성/강화/캐릭터) 정의
- [ ] 320×568, 390×844, 667×375, 844×390, PC 화면 검수
- [ ] 로비, 캐릭터 선택, 강화, 승리·실패 결과까지 동일 디자인 언어 적용
- [ ] 버튼 크기·텍스트 가독성·터치 영역·정보 가림 확인

### 4. 반응·대사·이펙트 (문제 2, 3)
- [ ] 소환/합성/동료 조합/위기/보스 처치 등 상황별 짧은 대사 설계
- [ ] 같은 대사의 과잉 반복 방지와 대사 우선순위/재생 간격 규칙
- [ ] 일반 공격/4성/특수 공격/적 피격 반응이 구별되도록 전투 피드백 강화
- [ ] 모션 감소·저사양 모드에서도 중요한 위험 정보는 전달

### 5. 다시 플레이할 이유 (문제 1, 8)
- [ ] 결과 화면에 도달 웨이브·패배 이유·발견 조합·개선한 기록 표시
- [ ] 난이도는 단순 체력·수량 증가가 아니라 새로운 판단을 요구하는지 검증
- [ ] 첫 판이 별도 장황한 설명 없이 조작을 이해하도록 구성
- [ ] 콘텐츠 밀도와 1판 약 10분 목표, 2~3분 첫 4성 목표 재점검

## 검증 규칙
- 코드가 존재하거나 정적 테스트에 통과했다고 시각적 완성도를 선언하지 않는다.
- 상용 게임 사례는 조작 체계, 시선 이동, 피드백을 참고하되 외형을 복제하지 않는다.
- 각 단계는 변경 코드/검증 결과/남은 미해결 사항을 함께 기록한다.
- 사용자 확인 전에는 되돌리기 쉬운 브랜치와 PR을 우선하며 `main`에 성급히 병합하지 않는다.
